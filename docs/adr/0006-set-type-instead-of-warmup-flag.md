# 以組類型取代熱身旗標，遞減與力竭都算正式組

組原本只有一個布林欄位 `isWarmup`。為了標示遞減組（Drop set）與力竭組，我們把它換成 `setType`（`regular`、`warmup`、`drop`、`failure`），並規定只有熱身不計入摘要、統計、上次紀錄、個人紀錄與新紀錄，遞減與力竭和一般的正式組一樣計入。另一個做法是讓遞減與力竭各自成為獨立的統計類別（例如遞減組不算最大重量），但那樣每個計算都得多一組規則，而這個 App 的目標是「快速記下做了什麼」，不是分析訓練科學；它們本來就是真的做了的組，訓練量也確實增加了。

## Consequences

- 「正式組」仍然定義為「不是熱身的組」，所以既有的計算（每日摘要、統計、上次紀錄、預填、逐組對照、個人紀錄）只要把 `!isWarmup` 換成同樣意義的判斷，行為不變。
- 資料模型改了：IndexedDB 升到 v3、匯出檔升到 schema v4，兩者都在升級時把 `isWarmup` 轉成 `setType`（`true` → `warmup`，`false` → `regular`）。升級是單向的：新版匯出的備份，舊版 App 會拒絕匯入。
- 新增組類型時，要同時決定它算不算正式組（會不會被各項計算排除），並更新 `nextSetType` 的順序與各處的標籤。

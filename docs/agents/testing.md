# 測試：寫測試前要知道的坑

測試只放兩個接縫：接縫 A（整個 App）與接縫 B（domain 公開函式），定義與範圍見 `docs/PRD.md` §9。這份文件只記從程式碼看不出來的事；E2E 與效能預算的坑在 `docs/agents/testing-e2e.md`。

## 接縫 A（Vitest + RTL）

- **一律用 `renderApp(route?)` 起手**（`src/test/renderApp.tsx`），它渲染真正的 `<App />`。`route` 不含 base path，例如 `renderApp('/exercises')`。
- **驗證「重新整理後仍保留」用 `reload()`**：`const { user, reload } = renderApp(...)`。它會卸載 App、關閉 db，再以目前網址重新渲染。
- **每個測試都從空資料庫開始**，`src/test/setup.ts` 自動處理，測試裡不用做任何事。原因：Dexie 在建立 db 時就固定了 `indexedDB`，只替換 `globalThis.indexedDB` 無效，所以 setup 改用 `db.delete({ disableAutoOpen: false })`。待寫的欄位編輯存在 localStorage，setup 也會一併 `localStorage.clear()`；新增其他存在 localStorage 的資料時不用另外清。
- **只有 `Date` 是假的**，固定在 2026-10-24（`src/test/fixedToday.ts`，E2E 共用）。`setTimeout` 等計時器是真的，所以 user-event、`findBy*`、toast 自動消失都照常運作。
- **今天以外的分頁是動態載入的**（code splitting，讓首次載入的 JS < 250 KB，見 `src/app/lazyPages.tsx`）：`renderApp('/exercises')` 或點分頁之後，第一個查詢要用 `findBy*`，即使那個元素不依賴資料（例如搜尋框、頁面標題）。訓練頁的日期選擇器、加入動作選單、選單裡的自訂動作表單也是第一次打開時才載入，但它們以 transition 等載入完成才打開，dialog 出現時內容已經在了，照原本用 `findByRole('dialog', …)` 等即可。`src/test/setup.ts` 在每個測試檔開始前先載入 `src/features` 的所有元件，避免第一次轉譯拖過 `findBy*` 的 1 秒逾時；新增動態載入的元件放在 `src/features` 底下就會自動涵蓋。
- **資料經 `useLiveData` 非同步載入**：清單、詳情等讀資料的畫面要用 `findBy*` 等待，不能用 `getBy*`。標題先出現、內容晚到的頁面也一樣，例如自訂動作表單要等動作庫載入（重名檢查用）才渲染，看到標題後還要 `findByRole('textbox', { name: '中文名稱' })`。
- **jsdom 缺的瀏覽器 API 在 `src/test/setup.ts` 補**：目前補了 `matchMedia`（sonner、主題）、`ResizeObserver`（Radix `Checkbox`、`RadioGroup`）與 `Element.prototype.setPointerCapture` 等 pointer capture 方法（點 sonner toast 上的按鈕）。新的 Radix 元件若在測試中出現 `XXX is not defined`，在同一處補空實作，不要在個別測試裡 mock。
- **sonner toast 跨測試殘留**：toast 存在 sonner 的模組層級狀態，`<Toaster />` 掛載時會重播還沒消失的 toast，所以上一個測試的「復原」按鈕會跑到下一個測試。`src/test/setup.ts` 的 `afterEach` 已呼叫 `toast.dismiss()`，新增 toast 不用再處理；但同一個測試裡連續刪除兩次，畫面上會同時有兩個「復原」，要先等前一個消失或改用 `getAllByRole`。
- **不要拿「可能重複出現的 toast」當作非同步動作完成的訊號**：同一個測試裡 `reload()` 也會重播還沒消失的 toast。若第二次動作後用 `findByText('匯入完成')` 等完成，它會比到第一次留下的 toast 而立刻返回；接著 `reload()` 或測試結束會關閉資料庫，中斷還在進行的寫入。這類失敗只在全套測試的負載下偶發，而且還會把寫入漏到下一個測試的新資料庫。等 toast 之前先 `toast.dismiss()`，並 `waitFor` 舊的 toast 消失（見 `src/test/importBackup.ts` 的 `dismissToasts`）。要確認一個等待是否可靠，可以暫時在 repository 方法開頭加 `await new Promise((r) => setTimeout(r, 300))`，正確的測試在延遲下仍會通過。
- **toast 的按鈕用 role 取**：`await screen.findByRole('button', { name: '復原' })`；訊息用 `findByText('已刪除一組')`。自動消失靠真實計時器，要驗證「約 5 秒後消失」只能真的等，測試要調高 timeout（例如 `it(..., 10_000)`），這類測試只寫一個。
- **刪除、排序後畫面是非同步更新**：寫入 IndexedDB 後由 live query 重新渲染，點完「刪除第 2 組」「上移」後用 `waitFor` 斷言結果，不要立刻 `getBy*`。
- **長字串用 `user.paste`**：測字數上限時 `user.type` 一字一字打很慢，先 `user.click(欄位)` 再 `user.paste('臥'.repeat(41))`。
- **shadcn／Radix 元件的實際 role**：
  - `ToggleGroup type="single"` 是 `radiogroup`／`radio`：`getByRole('radio', { name: '肩' })`、`toBeChecked()`
  - `RadioGroup` 同樣是 `radiogroup`／`radio`；`Checkbox` 是 `checkbox`，可用 `getAllByRole('checkbox', { checked: true })` 數勾選數
  - 自訂動作表單的部位多選是 `fieldset`，role 為 `group`：`within(getByRole('group', { name: '主要部位' })).getByRole('checkbox', { name: '胸' })`
  - `Switch` 是 `switch`
  - `<dl>` 的 `dd` 以 `aria-labelledby` 指向 `dt`：`getByRole('definition', { name: '記錄類型' })`
- **體重欄位在訓練頁的日期下方，載入後才出現**：`await screen.findByRole('textbox', { name: '體重（kg）' })`（lb 模式為「體重（lb）」）。它在名稱為「體重」的 `region` 裡，所以訓練頁上一直多一個 `region`。BMI 是純文字，用 `findByText('BMI 22.9')`；設定頁的身高欄位是 `getByRole('textbox', { name: '身高' })`。
- **測 IndexedDB 升級（舊版 App 留下的資料庫）用 `seedV1Database`**（`src/test/seedV1Database.ts`）：先以 v1 schema 寫入舊資料，再 `renderApp()` 讓 App 開啟時升級。feature 的測試檔不能 import `dexie`（ESLint 限制），以後再升版時，建立舊版資料庫的 helper 也放在 `src/test`。
- **今天頁的 `h1` 是日期**（固定日期下為 `10/24（六）`），不是「今天」。要確認在今天頁，用 `getByRole('heading', { level: 1, name: '10/24（六）' })`。
- **不要用 `getAllByRole('region')` 數訓練動作**：sonner 的 `<Toaster />` 一直掛在 App 上，它的 `<section aria-label="Notifications …">` 也是 `region`。每個訓練動作是以動作名稱命名的 `region`，用 `getByRole('region', { name: '槓鈴臥推' })` 取單一動作；要看順序，改數 `heading` level 2。
- **每日摘要是名稱為「每日摘要」的 `region`**，裡面是 `<dl>`，各項用 `definition` 取：`within(await screen.findByRole('region', { name: '每日摘要' })).getByRole('definition', { name: '總訓練量' })`。項目名稱是「動作數」「正式組數」「總訓練量」「有氧總時間」。數字是 live query 算出來的，輸入後要用 `waitFor` 等。範例見 `src/features/workout/dailySummary.test.tsx`。
- **`toHaveTextContent('0')` 是子字串比對**：會比到「10」「0 kg」，斷言單一數字時改比 `.textContent`（`expect(el.textContent).toBe('0')`）或用錨定的正規表示式。
- **確認對話框（shadcn `AlertDialog`）是 `alertdialog`**，名稱是標題：`findByRole('alertdialog', { name: '刪除「Smith 臥推」？' })`。對話框裡的確認鍵常和觸發鍵同名（例如都叫「刪除」），要用 `within(dialog)` 取。
- **斷言「沒有某個元素」前，先等相關資料載入完**：依非同步資料決定是否顯示的元素（例如動作詳情頁依「是否已有紀錄」顯示「封存」或「刪除」），載入中兩者都不在，直接 `queryBy*` 斷言不存在會在載入前就通過。先 `findBy*` 等一個載入後必定出現的元素，再斷言另一個不存在。
- **需要「已有紀錄」的動作時，透過 UI 在今天的訓練加入它**：建立自訂動作後切到「今天」分頁，從加入動作選單加入即可，不用填組數值。範例見 `src/features/exercises/archiveCustomExercises.test.tsx` 的 `createCustomWithRecord`。
- **加入動作選單是 `dialog`**，裡面的動作列是 `button`（動作庫分頁則是 `link`）。按鈕名稱是「中文名 英文名 · 器材」（例如「槓鈴臥推Barbell Bench Press · 槓鈴」），比對用 `{ name: /^槓鈴臥推/ }` 錨定開頭，避免名稱較短的關鍵字同時比到器材欄或其他動作。
- **做過的動作會同時出現在「最近使用」與「動作清單」**：只要任何一天的訓練有這個動作（包含剛在今天加入的），加入動作選單裡就有兩個同名按鈕，`within(dialog).getByRole('button', { name: /^槓鈴臥推/ })` 會因為比到多個而失敗。從全部動作選，先取清單：`within(within(dialog).getByRole('list', { name: '動作清單' })).getByRole('button', …)`；「最近使用」是名稱為「最近使用」的 `region`，裡面的清單也叫「最近使用」。範例見 `src/features/workout/addExercisePicker.test.tsx`。
- **在選單中「＋ 新增自訂動作」後，dialog 的名稱變成「新增自訂動作」**：表單在同一個 dialog 裡，`findByRole('dialog', { name: '新增自訂動作' })` 後用 `within` 填表；按「取消」回到名稱為「加入動作」的 dialog。
- **連續加入同一個動作時，不能用 `findByRole('region', { name })` 等它出現**：第二次加入時已經有一個同名的訓練動作，會比到多個；改等訓練動作數（h2 數量）增加，範例見 `addExercisePicker.test.tsx` 的 `addExercise`。
- **斷言目前網址時不要寫死 base path**：接縫 A 的 base 與正式環境不同，用 `` expect(window.location.pathname).toBe(`${import.meta.env.BASE_URL}day/2026-10-20`) ``；今天是 `import.meta.env.BASE_URL`（訓練頁切回今天時網址是 `/`，不是 `/day/<今天>`）。
- **日期選擇器（shadcn `Calendar`，react-day-picker 繁中語系）的實際 role 與名稱**：
  - 訓練頁的選擇器是 `Popover`，role 為 `dialog`：`findByRole('dialog', { name: '選擇日期' })`
  - 日期按鈕名稱是「2026年10月20日 星期二」，今天會加上「今天，」前綴，選取的日期加上「，已選取」後綴，所以用 `{ name: /10月20日/ }` 比對；未來日期用 `toBeDisabled()`
  - 星期標題列是 `aria-hidden`，查不到 `columnheader`。要驗證週一為一週第一天，看每個 `row` 裡第一個日期按鈕的名稱含「星期一」
  - 月曆本身是 `grid`，名稱是月份：`findByRole('grid', { name: '2026年10月' })`
  - 切換月份的按鈕是「前往上個月」「前往下個月」。不能再往後時是 `aria-disabled="true"`，**不是** `disabled`，`toBeDisabled()` 不會通過，要用 `toHaveAttribute('aria-disabled', 'true')`
  - 沒有設 `mode`（也沒有 `onDayClick`）時，日期只是 `gridcell`，不會渲染成 `button`；只拿來顯示的月曆也要設 `mode` 才查得到日期按鈕
- **歷史月曆（`/history`）的標點在日期按鈕的名稱上**：有訓練的日期名稱多了「，有訓練」後綴（例如「2026年10月20日 星期二，有訓練」），斷言用 `toHaveAccessibleName(/有訓練/)`。日期由 live query 載入，要用 `waitFor`；斷言某天「沒有標點」前，先 `waitFor` 另一個有訓練的日期出現標點，否則載入前就會通過。範例見 `src/features/history/historyCalendar.test.tsx`。
- **歷史的日明細是以 `M/D（週）` 命名的 `region`**（`findByRole('region', { name: '10/20（二）' })`），裡面有「每日摘要」、以動作名稱命名的 `article`（各組是名稱為「組」的 `list`，熱身組文字前面多了「熱身」，與動作歷史相同），以及 `link`「編輯」。
- **toast 在換頁後仍在**：sonner 的 `<Toaster />` 掛在 App 上，在訓練頁刪除後切到別的分頁，「復原」還按得到；先把 `findByRole('button', { name: '復原' })` 的結果存起來，換頁後再點。
- **`src/components/ui/calendar.tsx` 改過 shadcn 原版**：原版每次渲染都產生新的 `components`，react-day-picker 會重新掛載所有日期按鈕；父元件在點選途中因 live query 更新而重新渲染時，點選會遺失，測試約一成機率失敗。現在以 `useMemo` 固定。用 shadcn CLI 覆寫這個檔案時要保留這段；傳給 `Calendar` 的 `components` 也要是穩定的參考（模組常數或 `useMemo`）。自訂 `DayButton`（例如歷史月曆的標點）時，在模組層級定義元件與 `components` 物件，範例見 `src/features/history/HistoryPage.tsx`。
- **訓練動作區塊裡除了組的欄位，還有「備註」textbox**：要列出組的欄位時用 `getAllByRole('textbox', { name: /^第 \d+ 組/ })`，不要用沒有 name 的 `getAllByRole('textbox')`。
- **組的輸入欄位要讀 `.value` 時**，用 `getByRole<HTMLInputElement>('textbox', …)` 取得正確型別；單純斷言用 `toHaveValue('60')`（欄位是 `type="text"`，值是字串）。
- **組的欄位名稱依記錄類型而定**（N 為組的序號）：重量×次數是「第 N 組重量（kg）」「第 N 組次數」；次數是「第 N 組次數」「第 N 組額外負重（kg）」；時間是「第 N 組時間（mm:ss）」；距離＋時間是「第 N 組距離（km）」「第 N 組時間（mm:ss）」。時間重新載入後一律顯示成 `mm:ss`（例如輸入 `1:30` 或 `130`，重新整理後是 `01:30`）。
- **重量的欄位名稱與顯示跟著重量單位**：lb 模式下是「第 N 組重量（lb）」「第 N 組額外負重（lb）」，顯示四捨五入到 0.1 且固定 1 位小數（`135.0`、`132.3lb×8`、總訓練量 `1,058.2 lb`）；kg 最多顯示 2 位小數（135 lb 存成 kg 後顯示 `61.23`）。距離永遠是 km。
- **設定是非同步載入的，載入前先用預設值（kg、跟隨系統）**：App 一渲染就顯示畫面，`SettingsProvider` 讀到設定後才換成儲存的單位與主題。所以 lb 模式下 `reload()` 或剛渲染時，欄位名稱會先是「（kg）」再變成「（lb）」，要用 `findByRole` 等 lb 的名稱，不要 `getByRole`。設定頁則在載入完才顯示選項，用 `findByRole('radiogroup', { name: '重量單位' })`（另一個是「主題」），選項是 `radio`：`kg`、`lb`、`跟隨系統`、`淺色`、`深色`。點完選項後用 `waitFor` 等 `toBeChecked()`，確定已寫入再切頁或 `reload()`。範例見 `src/features/settings/settings.test.tsx`。
- **主題用 `<html>` 上的 `dark` class 斷言**：`document.documentElement.classList.contains('dark')`。setup 補的 `matchMedia` 一律不符合，所以接縫 A 裡「跟隨系統」就是淺色；系統深色只能在 E2E 用 `page.emulateMedia({ colorScheme: 'dark' })` 驗證（見 `e2e/theme.spec.ts`）。`dark` class 不會在 cleanup 時移除，要等下一個測試渲染 App 才依設定重設。
- **熱身標記是 `button`＋`aria-pressed`**（shadcn `Toggle`），名稱是「第 N 組熱身」：`within(card).getByRole('button', { name: '第 1 組熱身' })`，斷言用 `toHaveAttribute('aria-pressed', 'true')`。它是點一下的開關，走 `update` 而不是 `editField`，點完要先 `waitFor` 到 `aria-pressed` 改變，再 `reload()` 或切換日期，否則寫入可能還沒完成。每一組的列裡因此多了一個按鈕，數組裡的按鈕時要算進去。
- **建立「上次紀錄」用的歷史資料**：`renderApp('/day/2026-10-20')` 補記，再按「回到今天」或用日期選擇器切到別天後加入同一個動作，範例見 `src/features/workout/lastPerformance.test.tsx`。
- **「上次」那一列是非同步載入的，第一組預填則不是**：加入動作時就已經把上次紀錄的數值寫進第一組，所以欄位值可以直接 `toHaveValue`；「上次（M/D）：…」文字由 live query 讀出，要用 `findByText` 等。斷言某個動作「沒有上次紀錄」前，先 `findByText` 等另一個有上次紀錄的動作出現，確定已經載入完。
- **動作詳情頁的動作歷史**：清單是名稱為「歷史紀錄」的 `list`，每一天是以帶年份日期命名的 `article`（`findByRole('article', { name: '2026/10/20（二）' })`），裡面的日期是 `link`、各組是名稱為「組」的 `list`。熱身組的 `listitem` 文字前面多了「熱身」（例如 `熱身40kg×10`）。範例見 `src/features/exercises/exerciseHistory.test.tsx`。
- **需要很多天的紀錄時（例如測分批載入），從最早的日期 `renderApp('/day/…')` 開始，用「後一天」逐日加入動作**：不用填組數值，21 天約 1.5 秒；每次按「後一天」後先 `findByRole('heading', { level: 1, name })` 等日期標題換成新的日期，確定已切換再加入。
- **`user.type` 一字一字輸入，每個中間值都會被驗證，合法的就會寫入**：打 `60.555` 時 `60.55` 已經存下來；先 `clear` 再打不合法的值，清空那一下就寫入了 null。要驗證「保留上一個合法值」，選取全部再改打一個中間值都不合法的字串：`user.type(field, '00:60', { initialSelectionStart: 0, initialSelectionEnd: field.value.length })`。
- **欄位的驗證錯誤用 `toBeInvalid()` 與 `toHaveAccessibleDescription('錯誤訊息')` 斷言**：錯誤訊息以 `aria-describedby` 連到欄位，欄位帶 `aria-invalid`。`getByRole` 沒有 `invalid` 這個選項，傳了會被忽略。
- **domain 覆蓋率門檻（行 ≥ 80%）只在 `npm test -- --coverage` 時檢查**，單跑 `npm test` 不會擋。
- **需要既有資料（尤其是歷史資料）時，改用匯入 fixture 備份檔，不要透過 UI 逐筆輸入**：`await renderAppWithBackup(backupFixture({ workouts: [fixtureWorkout('2026-10-20', [...])] }), '/history')`（`src/test/importBackup.ts`、`src/test/backupFixture.ts`）。它先在設定頁匯入並確認，再從指定路由重新渲染。fixture 的 ID 是固定的：訓練動作 `fixture-<日期>-<第幾個動作>`、組 `fixture-<日期>-<第幾個動作>-<第幾組>`（從 1 起算）。匯入時會自動下載一份匯入前的備份，所以之後的 `waitForDownloads(n)` 要把它算進去（它是第 1 個）。範例見 `src/features/settings/backup.test.tsx`。
- **驗證下載的檔案用 `waitForDownloads(n)`**（`src/test/downloads.ts`）：setup 補了 `URL.createObjectURL` 並攔下 `<a download>` 的點擊，回傳依下載順序排列的 `{ fileName, text }`；沒下載用 `downloadCount()` 斷言為 0。新增下載功能時，連結要先加入 `document` 再 `click()`（見 `src/features/settings/downloadFile.ts`），否則點擊事件不會冒泡到 document，攔不到。
- **選擇檔案用 `user.upload`**：匯入的 `<input type="file">` 是隱藏的，用 `findByLabelText('選擇備份檔')` 取；`chooseBackupFile(user, 內容)` 已包好，字串會原樣當作檔案內容（用來測非 JSON 的檔案）。
- **模擬「剛輸入、還沒寫進資料庫」的欄位編輯時，要等資料庫開啟後才寫入 localStorage 的待寫清單**（`my-rep-book:pending-field-edits`）：透過 UI 輸入的話寫入幾乎立刻完成，測不出待寫清單的處理；但若在 `reload()` 或 `renderApp` 之後立刻寫入，資料庫開啟時的 `on('ready')` 會先把它補寫掉，測試就失去意義。先 `findBy*` 等一個依資料載入的元素出現再寫入，範例見 `backup.test.tsx` 的 `leavePendingEdit`。
- **jsdom 沒有 `navigator.storage`**：App 啟動時申請持久儲存，沒有它就當成「未啟用」。要模擬瀏覽器同意或拒絕，在 `renderApp` 之前呼叫 `fakeStorageManager({ grantsPersistence })`（`src/test/fakeStorageManager.ts`），測試結束自動移除。範例見 `src/features/settings/persistentStorage.test.tsx`。
- **接縫 A 不會註冊 Service Worker**：`virtual:pwa-register/react` 在 Vitest 中是 vite-plugin-pwa 提供的空實作，「有新版本」提示、離線都只能在 E2E 驗證。
